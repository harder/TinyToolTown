# Contributing to Tiny Tool Town

Thanks for helping grow the town! 🏘️ There are two main ways to contribute:
**submitting a tool** for the directory, and **improving the site** itself.

## Submitting a Tool

The easiest path — no code required:

1. [Open a new submission issue](https://github.com/shanselman/TinyToolTown/issues/new?template=submit-tool.yml)
   and fill out the form. (You can also use the external
   [TinyToolSubmitter](https://github.com/jamesmontemagno/TinyToolSubmitter) CLI,
   which generates and opens the issue for you.)
2. Automated triage (`triage-tool.yml`) checks that the repo exists, is public,
   has a README, and has an open-source license, then labels the issue.
3. A maintainer reviews and labels it `approved`.
4. The batch importer (`batch-approve.yml`) generates the tool's page, thumbnail,
   and social card, and the site redeploys automatically.

To qualify, a tool should be:

- **Free and open source** (a real `LICENSE` file in the repo — MIT is a great choice).
- **Tiny and fun / genuinely useful** — not enterprise software or paid SaaS.
- **Public and working**, with a `README.md`. A screenshot or demo image helps a lot.

Each repository can be listed once — duplicate submissions of an already-listed
repo are detected automatically and won't create a second page.

## Improving the Site

This is an [Astro](https://astro.build) static site.

### Prerequisites

- Node.js **24** (matches CI and the deploy workflows).

### Setup

```bash
npm ci             # install exact dependencies
npm run dev        # local dev server
```

### Useful scripts

| Command            | What it does                                                        |
| ------------------ | ------------------------------------------------------------------- |
| `npm run dev`      | Start the local dev server.                                         |
| `npm run build`    | Production build into `dist/`.                                      |
| `npm run preview`  | Preview the production build locally.                               |
| `npm test`         | Run the Vitest test suite.                                          |
| `npm run social`   | (Re)generate static social cards into `public/social/` incrementally. |

### Before opening a pull request

Please run, and make sure all pass:

```bash
npm ci
npm test
npm run build
```

CI (`.github/workflows/ci.yml`) runs the same three commands on every PR.

### Project layout

- `src/content/tools/*.md` — one markdown file per tool. Schema in `src/content.config.ts`.
- `src/pages/`, `src/components/`, `src/layouts/` — Astro pages, components, and layouts.
- `src/lib/` — shared helpers (and `__tests__/` for unit tests).
- `scripts/` — Node maintenance scripts (thumbnails, stars, social cards, the
  shared issue-form parser used by the automation workflows).
- `.github/workflows/` — submission triage, batch import, deploy, and refresh jobs.

### Conventions

- Keep changes focused; don't reformat unrelated code.
- Add or update tests when you change parsing or other logic in `scripts/` or `src/lib/`.
- Tool frontmatter fields `ai_summary` / `ai_features` are generated by automation —
  don't hand-edit them.

## Code of Conduct

Be kind and welcoming. This is a small, friendly community project — treat fellow
contributors and tool authors with respect.
